# ОРБИТАЛЬ (ball-merging-defense) — технический контекст

Документ описывает проект целиком: назначение, архитектуру, правила и
формулы, внутреннее устройство движка, систему автоматического
тестирования и накопленный опыт. Предназначен для быстрого входа нового
исполнителя и для сохранения решений, которые иначе потерялись бы в
истории переписки.

Дата фиксации: 11 октября 2026 года.

## 1. Назначение

ОРБИТАЛЬ — одиночная браузерная игра жанра «оборона с управлением
полем». Игрок управляет решёткой из двадцати четырёх клеток, каждая
клетка содержит шарик одного из нескольких типов. Шарики стреляют по
врагам, движущимся по кольцевой трассе вокруг поля. Выход врага за
конец трассы отнимает жизнь; исчерпание жизней завершает игру.

Ресурсом развития является эссенция: она тратится на глобальные
улучшения типов и возвращается за продажу заряженных шариков. Игровой
процесс построен на двух взаимодополняющих режимах — «Совмещение»
(выстрелы парами и цепями) и «Накопление» (слияние шариков в заряженные).
Между забегами — мета-прогресс: главное меню, колода из шести шариков,
магазин, валюта и деревья навыков (раздел 17).

## 2. Запуск и сборка

Итоговый артефакт — единый файл `index.html` (собран плагином
vite:singlefile, все зависимости встроены). Для игры установка
окружения не требуется: файл открывается двойным щелчком, работает по
протоколу file. Модульный скрипт в файле выполняется браузером без
ошибок; внешние ресурсы отсутствуют.

Сборка при разработке:

```
cd ball-merging-defense
npm install        # один раз
npx tsc --noEmit   # проверка типов
npm run build      # пересборка index.html
```

Правило проекта: любой правке исходников должна предшествовать
пересборка `index.html`, так как пользователь играет именно с этим
файлом, а не с разработочным сервером.

## 4. Геометрия

Сцена имеет размер 640 на 880 условных единиц, масштабруется под
контейнер. Поле — решётка 4 на 6 клеток, клетка 80 единиц, зазор 12.
Левый верхний угол поля — точка (142, 182); центр клетки с индексом i
рассчитывается как:

```
x = 142 + (i % 4) * 92 + 40
y = 182 + floor(i / 4) * 92 + 40
```

Трасса — скруглённый прямоугольник: угловые дуги радиуса 40,
прямые стороны. Длина трассы (периметр) приблизительно 2331.3;
враг покидает игру по достижении отметки LEAK_AT = периметр минус 140,
то есть приблизительно 2191.3. Стартовая точка — верхний левый угол.
Координаты точки трассы по пройденному пути даёт функция `pathPoint(p)`.

## 5. Ход игры

Состояния движка: `prep` (подготовка к волне), `wave` (идёт волна),
`gameover`. Заставки нет: приложение открывается в главном меню, а
движок создаётся заново на каждый забег (`startGame(cfg)`, где `cfg` —
колода, эффекты деревьев и запасы из меты). Пауза «Завершить забег»
вызывает `surrender()`: забег переходит в `gameover`, награда та же.

- Подготовка перед первой волной — 9 секунд, между волнами — 6.
  Досрочный вызов волны кнопкой даёт 5 эссенции.
- На волне N врагов: 5 + 2*N, плюс босс на каждой пятой волне.
- Здоровье обычного врага: 6 × 1.12^(N−1), округляется.
  Скорость: 62 px/с на первой волне, рост 1.4 раза, потолок 92.
  Награда — 2 эссенции.
- Босс: здоровье 45 × 1.35^(к-1) по номеру босс-волны, скорость 46,
  награда 20, при утечке забирает 5 жизней. Перед босс-волной
  открывается рулетка выбора босса.
- Зачистка волны приносит 8 + номер волны эссенции.
- Жизней 20; утечка обычного врага отнимает одну жизнь.

### 5.1. Заряжающийся моб

- Появляется в начале трассы вместе с обычными мобами: на волне от
  `CONFIG.charger.fromWave` (2-й) с долей `chance` (0.2) среди обычных
  мобов. В боссовых волнах не появляется. Код в плане спавна —
  `CHARGER_KIND = 3`.
- При создании выбирает время зарядки T случайно из диапазона
  `chargeMin…chargeMax` (3–8 с). T хранится в моба (`chargeT`), `bornAt` —
  время появления. Заряд = (время жизни / T), от 0 до 1 (`charger.ts`,
  `chargeProgress`).
- Здоровье, скорость и награда — как у обычного моба. Единственное
  отличие — поведение при смерти и цвет.
- Цвет тела (`chargeTint`): серый (как у обычного) → сиреневый при
  заряде 1. При полном заряде тело светится, по контуру пульсирует
  сиреневое кольцо.
- Убит при заряде ≥ 1 — на трассе в точке смерти появляется **лужа
  эликсира** (`spawnPuddle`): полоса вдоль трассы радиусом
  `puddleRadius` (70 px в обе стороны по дистанции), держится
  `puddleDuration` (8 с), в последние 1.5 с гаснет. Убит до полной зарядки —
  лужи нет. Утечка (выход за трассу) лужи не даёт: это не смерть.
- Лужа ускоряет мобов в радиусе: скорость × `puddleSpeed` (1.6). Лужи не
  складываются: эффект такой же, даже если лужи перекрываются. Боссы
  не затрагиваются, пока `puddleBoss = false`. Сам заряжающийся моб
  погибает, поэтому на себя лужа не действует.
- Все цифры — в `CONFIG.charger` (config.ts).

## 6. Улучшения, продажа, автозаполнение

- Улучшение по типам: удержание шарика на поле около 0.48 секунды
  устраняет шарик и повышает уровень его типа в колоде на один.
  Стоимость фиксирована — 100 эссенций. Уровень типа влияет на формулы
  всех шариков этого типа (см. раздел 8); ограничение уровня типа
  отсутствует.
- Продажа шарика — 5 эссенций плюс 3 за каждый уровень заряда сверх
  первого (шарик заряда 3 продаётся за 11).
- Пустые клетки заполняются автоматически каждые 2 секунды: в каждую
  пустую клетку ставится случайный шарик из текущей колоды.

## 7. Режимы и управление

### 7.1. Совмещение

Целью режима является одновременный выстрел группы шариков.

- Пара: тап по одному шарику, затем по соседнему. Оба шарика одного
  типа стреляют по два снаряда с бонусом +2 к урону.
- Цепь: проводка линий мыши или пальцем по двум и более соседним
  шарикам; зигзаги и углы допустимы. Каждый шарик линии стреляет по
  два снаряда; бонус к урону равен числу шариков в линии. Комбо-бонус
  применяется ко всем снарядам всей линии.
- Правило одинаковости: линия строится из шариков одного типа.
  Исключение — шипастый: он допускается в любую линию (решение
  одиннадцатого требования). Шипастый в линии не стреляет: он
  лопается, и его иглы разрушают шарики и ранят врагов.
- После выстрела все задействованные шарики уходят в перезарядку на
  1.3 секунды. Повтор линии допустим после перезарядки.
- При протягивании линии через шипастый он лопается немедленно в
  момент добавления, а не в момент отпускания.

### 7.2. Накопление

Режим отключает выстрелы. Тап-тап по двум соседним шарикам сливает их
в один: уровни заряда складываются (шарик заряда 5 и шарик заряда 3
дают заряд 8). Максимальный заряд — 9. Заряд сохраняется на шарике,
нажатом вторым; тип результатом слияния берётся с шарика, нажатого
вторым. Шипастый допускается к слиянию с любым типом.

Возврат в режим «Совмещение» вызывает детонацию всех заряженных
шариков: каждый выпускает залп, равный уровню заряда. Заряженный
шипастый при детонации выпускает иглы, а не снаряды. Залп удваивается,
если рядом стоит усилитель.

Урон накопления (решение, раздел 17.7): залп заряженного шарика
усиливается множителем `accumMul(level) = 1 + level × 0.02` (только для
заряда 2 и выше). Множитель применяется ко всем снарядам этого залпа и
к иглам заряженного шипастого; заряд 9 даёт ×1.18.

### 7.3. Жесты и клавиши

| Действие | Жест |
| --- | --- |

| Улучшение типа | удержание шарика на поле 0.48 с |

## 8. Типы шариков

Переменная g — превышение уровня типа в колоде над базовым
(g = уровень − 1); переменная b — комбо-бонус линии (равен числу
шариков линии, для пары — 2).

| Тип | Основное действие при попадании | Формулы |
| --- | --- | --- |
| Огонь | урон цели и осколки соседним врагам | цель 3+g+b; соседям в пределах 58 px — 1 |
| Лёд | урон и замедление цели | урон 1+b; замедление до max(0.15, 0.55−0.05g) скорости; длительность 2.3+0.4g с |
| Молния | урон цели и ближайшим в радиусе | цель и (1+g) ближайших в радиусе 150+30g по 2+g+b |
| Яд | урон и отравление | урон 1+b; яд 1.2+0.6g урона в секунду до 4+0.5g с; максимум 4 стака, новый стак продлевает слабейший |
| Шипастый | не стреляет; лопается при соединении и от игл | 4+g игл; урон иглы врагу 1+g |
| Усилитель | даёт 4 соседним шарикам эффект усиления (серые стрелочки из центра) и удваивает их снаряды при выстреле в режиме совмещения и при взрыве | собственный эхо-снаряд 1+g+b |
| Сверхновая (сундук) | урон всем в радиусе | 4+g+b в радиусе 95+20g |
| Паралич (сундук) | урон и остановка цели | 1+b; 1.2+0.4g с |
| Пробой (сундук) | прямой снаряд без наведения | 2+g; пробивает 2+g врагов на линии |
| Вампир (сундук) | урон и добыча эссенции | 1+g+b; +1 эссенция за попадание, не чаще раза в 0.35 с (узел дерева добавляет эссенцию за каждое попадание без дросселя) |
| Метка (сундук) | ставит метку на случайного живого врага; метка жжёт врага и высасывает из него эссенцию | удар 1+g+b; метка 1+0.5g урона в секунду, 3.5+0.5g с; меток на враге не больше 2+стаков (новая метка при полном лимите заменяет самую короткую); урон меток → эссенция: `CONFIG.markDrain` = 0.5 за единицу урона, без опыта |
| Шквал (сундук) | залп из нескольких снарядов | max(заряд, 5+g) снарядов |

Снаряды наводятся на цель и движутся со скоростью до 520 px/с;
жизнь снаряда 3 секунды.

Стартовые шесть типов (огонь, лёд, молния, яд, шипастый, усилитель)
открыты с начала. Остальные шесть (сверхновая, паралич, пробой, вампир,
метка, шквал) открываются сундуками (ежедневным и после забега). Всего 12 типов. В забеге поле заполняется
только шариками колоды; колода — ровно шесть шариков (раздел 17.5).
Экспериментального режима с меняющейся каждую пятую волну колодой
больше нет.

Эссенция больше не начисляется за каждый залп. Её дают: вампир (базовая
эссенция за попадание, дроссель 0.35 с; узлы дерева добавляют ещё),
шипастый (только узлы дерева, за взрыв), а также убийства, зачистка
волны и досрочный вызов, как и раньше.

Шанс крита (`crit`, узел дерева) — попадание наносит двойной урон.
Высасывание меток (`drain`, узел дерева) — добавка к коэффициенту эссенции меток: эссенция = урон метки × `CONFIG.markDrain` × (1 + drain). Опыта у меток нет; дробная часть копится (`markDrainAcc`) и даёт целую эссенцию.

## 9. Шипастый и иглы

Лопнувший шипастый выпускает 4+g игл: четыре иглы по сторонам света
(вверх, вправо, вниз, влево) и избыток, распределённый между ними.
Игла стартует от края клетки (смещение 24 px), движется прямо со
скоростью 540 px/с, живёт 1.6 секунды.

Игла действует на два класса целей:

- Шарики. Игла разрушает первый шарик на пути. Любой разрушенный шарик
  ставится в очередь лопания и выпускает снаряды по своему уровню заряда
  (удваивается, если рядом стоит усилитель). Если разрушенный шарик
  шипастый — срабатывает цепная реакция: его иглы продолжат линию.
- Враги. Игла наносит врагу 1+g урона (g — уровень шипастого в
  колоде) и гибнет.

Цепочное разрушение учитывается счётчиком: когда иглы погасли и
очередь пуста, счётчик завершает реакцию. Цепь из четырёх и более
взрывов приносит бонус 3 и более эссенции (счётчик минус 1);
максимальная реакция сохраняется для статистики.

## 10. Внутреннее устройство шага

Метод `step(dt)` выполняется в следующей последовательности:

1. Увеличение времени `now`.
2. Подготовка: по истечении паузы — старт волны.
3. Автозаполнение пустых клеток (период 2 с).
4. Спавн врагов по плану волны.
5. Движение врагов, прогон эффектов (замедление, паралич, яд),
   утечка, смерть.
6. Проверка поражения и зачистки волны.
7. Полёт снарядов и попадания.
8. Полёт игл и их столкновения.
9. Обработка очереди лопания `popQueue`.

Очередь лопания существует для того, чтобы заряженный шарик не был
уничтожен дважды в одном кадре (например, иглой и сменой режима
одновременно). Клетка заряженного шарика помечается множеством
`popQueued`; пометка снимается строго в момент обработки очереди.
Критическое правило: обычный (незаряженный) шарик, разрушенный иглой,
пометке не подлежит — клетка освобождается немедленно, иначе свежий
шарик автозаполнения оказывался бы невидимым для игл и детонаций,
пока пометка не была снята. Это исправление (пункт одиннадцатого
требования, подпункт б) покрыто регрессионными тестами F5a и F5b.

## 11. Экраны интерфейса

- Экран входа (`LoginScreen.tsx`): логин и пароль, режимы «Вход» и
  «Регистрация». Без входа игра не открывается.
- Главное меню (`MainMenu.tsx`): «Играть», «Магазин», «Инвентарь» — кнопки
  внизу в одном ряду в стиле «Магазин». Сверху — рекорд слева; справа —
  монеты, имя аккаунта и кнопка выхода. Стиль — глянцевые светящиеся шары.
- Инвентарь: шесть слотов колоды (тап по шарику в коллекции — в колоду
  или из неё), сетка всех двенадцати шариков с прогрессом дерева.
  Вкладка «Дерево» в окне шарика прокручивается вниз.
  Зажатие шарика открывает окно шарика.
- Магазин: ежедневный сундук (раз в локальный день), покупка ОП за монеты
  для открытых шариков, запасы на забег (эссенция, жизни). Шарики в магазине
  не продаются.
- Окно шарика: «Описание» (характеристики первого уровня, бонусы
  дерева, покупка) и «Дерево» (схема узлов, предпросмотр тянется вверх
  и вниз или колесом мыши; карточка выбранного узла; сброс дерева).
- Верхняя панель забега: номер волны, жизни, эссенция; справа — пауза,
  скорость, звук, справка.
- Внизу — колода из шести слотов с уровнем каждого типа; удержание
  открывает панель статов и бонусов дерева («сейчас / после улучшения»).
- Пауза: «Продолжить» и «Завершить забег» (награда за пройденные волны).
- Справка: текстовое описание правил; содержит правило об
  исключении шипастого.
- Конец забега: счёт, статистика, награда (монеты, ОП по шарикам колоды, сундук после забега),
  кнопки «Играть снова» (новый движок и новый забег) и «В меню».
- Рулетка босса: открывается на подготовке перед каждой пятой волной.

## 12. Тестирование

Автоматический набор проверок расположен вне репозитория:
`~/.qa/orbital/checks_orbital.mjs` (71 проверка, группы A–M и K).
Набор выполняет игру в headless-браузере и управляет движком напрямую
через точку доступа `window.__orbital.g`.

### 12.1. Структура групп

- A — запуск, наполнение поля, состав колоды.
- B — пары: бонус, одинаковость, шипастый, перезарядка, урон.
- C — цепи: бонус от длины, шипастый в цепи, частичная перезарядка.
- D — управляющие жесты: линия мышью, старт со шипастого, ошибки.
- E — слияния: заряд на втором, тип второго, складывание, потолок 9,
  исключение шипастого.
- F — детонации сменой режима: залпы, усилитель, пустое поле,
  регрессии «залипшей» клетки (F5a, F5b).
- G — иглы: разрушение, цепные реакции, урон врагам, число игл,
  бонус за длинную реакцию.
- H — попадания каждого типа: урон, эффекты, прокачка по уровням.
- I — волны: спавн, утечка, награда, зачистка, поражение.
- J — улучшения, продажа, автозаполнение, досрочный вызов.
- K — (устарело: экспериментального режима больше нет) босс-волна.
- M — интерфейс: рестарт, режим, колода, справка, пауза, статы.
- Группы A, K, M описывают прежнюю заставку и колоду из пяти случайных
  типов; при следующем прогоне их нужно переписать под главное меню
  и колоду из шести.

### 12.2. Детерминированные часы

В headless-браузере метки времени requestAnimationFrame смещены
относительно performance.now и периодически перестают поступать
(особенность программной графической подсистемы). Игровой цикл
при таких условиях ведёт время движка с дрейфом и останавливается.
Поэтому набор отключает автоматический прогресс: метод `step`
экземпляра заменяется пустой функцией, исходный сохраняется в
`__step0`, и каждая пауза теста дополнительно прогоняет движок
явными шагами по 1/60 секунды. После пересоздания движка кнопкой
«Играть снова» затенение повторяется автоматически.

### 12.3. Запуск

Окружение разово настраивается скриптом `setup_env.sh` (см. раздел 14).
Прогон:

```
cd ~/.qa/orbital
LD_LIBRARY_PATH=/tmp/al2023/lib:/tmp \
FONTCONFIG_FILE=/tmp/fonts/fonts.conf \
node checks_orbital.mjs
```

Итог: «N из 71 проверок пройдено». Требуемый критерий приёмки —
три последовательных полных прогона без единого сбоя.

В сессии итерации «главное меню» набор `~/.qa/orbital` отсутствовал, а
headless-браузер (chromium) не нашёлся. Поэтому проверки делались так:
- сборка `npx tsc --noEmit` и `npm run build` (чисто);
- headless-проверки движка и меты через esbuild-бандл в Node (64
  проверки: дерево, накопление, экономика, колода, сундук, запасы,
  сброс, smoke-прогон 18 волн без исключений; скрипт вне репозитория);
- рендер всех экранов через `react-dom/server` с заглушками DOM (без
  ошибок и `NaN`).
Интерактивные жесты (перетаскивание дерева, удержание шарика) в
браузере не проверены — это нужно сделать вручную или набором.

## 13. Ограничения песочницы и особенности среды

- Сетевой доступ ограничивается npm-реестром и GitHub; пакетные
  менеджеры системы и хранилища Google недоступны.
- Системный браузер отсутствует; headless-ядро берётся из пакета
  @sparticuz/chromium, который распаковывается в /tmp.
- Графическая подсистема — программный рендерер SwiftShader; он
  медленно стартовал и периодически прекращает выдавать кадры. Это
  не ошибка игры: в настоящем браузере кадры поступают непрерывно.
  Наблюдаемые следствия (отрицательное игровое время, «залипшие»
  вспышки на скриншотах) устраняются описанным в разделе 12.2
  механизмом и ограничением яркости вспышек в отрисовке.
- Содержимое /tmp не сохраняется между сессиями; перед тестами
  требуется повторный запуск setup_env.sh и пересборка окружения.

## 14. История требований и ключевые решения

1. Белый экран исправлен; объяснён запуск с GitHub; начальный набор
   багов устранён.
2. Игра должна запускаться двойным щелчком по index.html без
   установки окружения.
3. Интерфейс без вспомогательных символов: надписи — обычными
   словами; описания способностей — техническим стилем.
4. Дизайн плоский: без свечения и градиентов на шариках.
5. Усилитель получил тёмные звуковые волны на светлом шарике.
6. Слияние сохраняет заряд на шарике, нажатом вторым.
7. Заряд складывается (5 и 3 дают 8); колода вынесена вниз.
8. Символы на шариках; огненный — пламя.
9. Улучшения перенесены на уровни типов; цена 100; шипастые
   ослаблены, поздние волны смягчены; панели статов.
10. Цепь — только из одинаковых шариков; комбо-урон +1 за шарик
    линии; тип усилителя (удвоение залпа соседа).
11. Шипастый соединяется с любым шариком в обоих режимах; тип
    слияния — со второго нажатого; иглы ранят врагов (урон 1+g,
    игла гибнет); пара даёт +2; исправлена «залипшая» клетка.
12. Главное меню вместо заставки: экспериментальный режим и заставка с
    описаниями удалены. Введены колода из шести шариков, инвентарь,
    магазин с ежедневным сундуком, монеты и очки прокачки, деревья
    навыков у каждого шарика (стиль Outhold). Накопление: урон залпа
    умножается на `1 + заряд × 0.02` (раздел 17.7).
13. Дерево навыков переделано с трёх линий на ветвящуюся схему с
    развилками A/B (взаимоисключающий выбор). Добавлен шарик «Метка»
    (900 монет): ставит метки на случайных врагов, метки дают урон и
    опыт шарику. Главное меню переделано под референс: янтарные шары,
    кнопки «Играть» и «Инвентарь», магазин и сундук — плавающими шарами.
    Эссенция за залп убрана; вампир и шипастый получают её по событию.
14. Метка: опыт убран, урон меток высасывает эссенцию из мобов (без роста
    уровня от самой метки). Очки прокачки стали отдельными у каждого шарика
    (ОП); сундук даёт ОП конкретному шарику, неоткрытый шарик открывается
    его первым ОП. Стоимость узлов растёт (n-й узел дерева стоит n ОП).
    Деревья: 11 узлов + корень, два уровня выбора. Введён вход по логину и
    паролю с облачным сохранением (Firebase, Firestore `players/{uid}`).
15. Заряжающийся моб (раздел 5.1): T выбирается при создании, серый →
    сиреневый, убит полностью заряженным оставляет лужу эликсира на трассе,
    которая ускоряет мобов в радиусе. Радиус, длительность и скорость
    настраиваются в `CONFIG.charger`.


## 15. Известные несоответствия и уроки

- Замедление льда: раньше панель статов обещала предел 0.15, а движок
  ограничивал 0.2. Устранено: и панель, и движок используют
  `max(0.15, 0.55 − 0.05g)`; проверено тестом (бонус дерева не опускает
  множитель ниже 0.15).
- Ошибки ожидания в тестах исправлялись по результатам прогона:
  урон иглы третьего уровня равен 3 (не 2); в паре и цепи стреляют
  только нешипастые шарики; точка утечки на трассе — 2191.3, а не
  2125.3; яд продолжает ранить после попадания, поэтому проверка
  здоровья должна допускать диапазон.
- Синхронизация с мобильного клиента случайно переименовала файлы
  движка в «корзину» (коммит «Last sync (Mobile)»); имена возвращены
  отдельным коммитом. При пуше с телефона за состоянием ветки
  рекомендуется следить.
- Тест ожидания конца игры должен быть изолирован пробным блоком:
  тайм-аут ожидания превращался в аварийное завершение всего набора.
- Метки: истёкшая метка снимается до тика. Раньше последний тик
  истёкшей метки всё равно бил врага.
- Headless-тесты не должны зависеть от случайного автодозаполнения
  сетки: в тестах детонации отключён `nextAutoFill` и считаются вызовы
  `fireOrbAt`. Смоук-тест, который брал всегда первую пару, не давал
  шарикам «Метка» ни одного выстрела; выбор пары теперь случайный.

## 16. Текущее состояние

Трасса и поле (текущая итерация, кооператив «как в Random Dice»):
- Трасса одна для обоих полей — `TRACK_PTS` (config.ts): спавн (26, 550) слева
  внизу своего поля, вверх по левому краю до верхней кромки (это общая линия
  посередине), вправо до выхода (614, 0). `PERIMETER` ≈ 1138.
  `PATH_SPEED_SCALE` = 1847.3 / PERIMETER сохраняет время прохода прежнего кольца.
- Холст кооператива — один, 640 × 1240 (`GameStage`, `VIEW_OWN` / `VIEW_REMOTE`).
  Моё поле внизу без поворота (сдвиг на 620). Поле напарника вверху, зеркально по
  вертикали: его точка (x, y) → мир (x, 620 − y). Тогда спавн напарника слева вверху,
  а оба пути сходятся на общей линии (мир y = 620) и идут к одному выходу справа.
- Статический слой (фоны и трасса) строится один раз на размер и режим
  (`getStaticLayer`). Поля стыкуются без рамок и зазоров: фоны → внешняя кромка
  всех трасс → светлые линии. Так общая линия видна целиком.
- Подписи (`uText`) рисуются в мировых координатах, поэтому не зеркалятся.
  Статус и баннер — только у моего поля (`drawScene` с `opts.chrome`).
- Касания — только по моему полю: координаты переводятся в мою систему (`toStage`).
- Сохранение матча: `game/runSave.ts` пишет состояние движка раз в секунду в
  localStorage (`orbital.run.v1`), пока идёт бой. Обновление страницы
  возвращает матч: соло — на паузе; кооператив — после входа в тот же аккаунт и
  если комната ещё открыта. Мета (монеты, колода, деревья) хранится отдельно.
- Выход из матча (кооператив): кнопка «Выйти из матча» в панели управления,
  подтверждение по центру. Флаг `rooms/{code}/left/{uid}`: поле напарника
  серое, его враги замирают, волны стартуют без него.
- Ник напарника показан подписью «Напарник: логин» над его полем.

Кооператив по сети (два телефона), текущая итерация:
- Вход: кнопка «Вдвоём» в главном меню (нужен вход в аккаунт и колода). Лобби

## 17. Мета-прогресс, деревья навыков и накопление

### 17.1. Поток экранов

Запуск: экран входа (`LoginScreen.tsx`) — без входа игра не открывается.
После входа облачная мета загружается, открывается главное меню
(`MainMenu.tsx`): «Играть», «Магазин», «Инвентарь». Экран игры создаётся
на каждый забег. Состояние `meta` лежит в `App.tsx`; все изменения идут
через `updateMeta(fn)`. Автосохранение: локальная копия сразу, облако —
через `scheduleCloudSave` (задержка 0.8 с), при сворачивании вкладки и
закрытии страницы — `flushCloudSave`.

### 17.2. Хранение

- Облако (основное): Firestore, документ `players/{uid}` с полями `meta`,
  `login`, `createdAt`, `updatedAt` (`services/playProfile.ts`). Правила
  доступа — `firestore.rules`: игрок читает и пишет только свой документ.
- Локальная копия (кэш устройства): localStorage, ключ `orbital.meta.v1`.
  При выходе удаляется (`clearLocalMeta`), чтобы следующий игрок не видел
  чужую мету. Из кэша мета при входе не читается: источник — облако.
- Разбор сохранения — одна функция `parseMeta` для облака и кэша; любой
  мусор заменяется значениями по умолчанию.
- Поля `MetaState`: `coins` (монеты, общие), `pts` (очки прокачки по
  шарикам, `Record<OrbType, number>`), `owned`, `deck`, `nodes`, `boosts`,
  `chestDay`, `runs`, `bestWave`.
- Миграция старого сохранения (до очков по шарикам): общее число `points`
  раздаётся открытым шарикам поровну, остаток — первым.

### 17.3. Валюта, очки прокачки и награда

- Монеты (`coins`) — общие. Тратятся в магазине (запасы, покупка ОП) и на
  узлы деревьев. В шапке меню и магазина показан только чип монет.
- Очки прокачки (ОП) — отдельно у каждого шарика, `pts[тип]`. Тратятся
  только на узлы дерева этого шарика. Видны в инвентаре (на плитке шарика)
  и в окне шарика.
- Награда за забег (`settleRun`, один раз на забег, чистая функция):
  пройденные волны `passed = wave − 1`; монеты `Σ_{w=1..passed}(10 + 3w)`;
  ОП за волны = `passed × 3` (`META_CFG.pointsPerWave`), делятся поровну
  между 6 шариками колоды (остаток — первым шарикам, `splitPoints`).
  Пример: дошёл до 18-й волны (пройдено 17): 629 монет и 51 ОП — по 8–9 на
  шарик колоды.
- Награда начисляется при поражении (`gameover`) и при «Завершить забег»
  (`surrender`). Повторного начисления за тот же забег нет (`rewardedFor`).
  Сундук после забега бросается в том же месте (`rollChest`), один раз.

### 17.4. Сундуки

Одна таблица для ежедневного сундука и сундука после каждого забега
(`rollChest`, `applyChest`):

- монеты 60–150;
- ОП 1–3 одному случайному шарику из двенадцати;
- редкий легендарный бросок — шанс 1 из 50: ОП 6–10 одному шарику;
- если шарика ещё нет, его ОП открывают (`owned` пополняется, `opened`);
- легендарный дубликат (шарик уже открыт): дополнительно +120 монет в общий
  баланс (`dupCoins`). Обычный дубликат — только ОП.

Ежедневный сундук: раз в локальный день (`chestReady`, `chestDay`).

### 17.5. Магазин

- Шарики в магазине не продаются: открываются только сундуками. Шесть
  стартовых открыты с начала.
- Очки прокачки (`buyPoints`): пачка 5 ОП за 125 монет (25 монет за ОП),
  только для открытых шариков.
- Запасы на забег (`buyBoost`, `boosts`): эссенция +40 за 120 монет,
  жизни +5 за 200 монет. Покупается штука на забег; расходуется при
  `startRun`.

### 17.6. Колода

- Колода — ровно `META_CFG.deckSize = 6` шариков. «Играть» заблокировано
  при другом количестве.
- В инвентаре тап по открытому шарику добавляет его в колоду или убирает
  (`toggleDeck`). Закрытый шарик в колоду не войдёт.
- В забеге поле заполняется только шариками колоды (`refillField` берёт
  типы из `deck`); уровни типов обнуляются на старте забега.

### 17.7. Накопление: трактовка урона

Формула из запроса: `(индекс накопления × 2 / 100)` — процент, который
умножается на урон всех выстрелившим снарядам. Принятая трактовка:
множитель урона залпа `accumMul(level) = 1 + level × 0.02` для
`level ≥ 2` (иначе 1). Это бонус к единице, а не умножение урона на
процент: буквальное «урон × 0.02» обнулило бы урон.

- Заряд 2 → ×1.04; заряд 5 → ×1.10; заряд 9 → ×1.18.
- Применяется к снарядам залпа заряженного шарика при детонации
  (возврат в «Совмещение», лопание иглой) и к иглам заряженного
  шипастого (`NeedleState.dmgMul`).
- Множитель действует на весь урон этого попадания снаряда: основной
  удар, осколки огня, цепи молнии, взрывы (`impact` выставляет `hitMul`
  и сбрасывает его в `finally`). Тики яда и остальные уроны вне
  попадания не умножаются.
- Константа `CONFIG.accumDmgPerLevel = 0.02` — единственная точка
  правки. Если пользователь выберет другую трактовку, менять `accumMul`.

### 17.8. Деревья навыков (`skills.ts`)

- У каждого из 12 типов своё дерево: корень (открыт всегда), 11 узлов.
  Всего 132 узла. Схема одна для всех типов (`TREE_SLOTS`), содержание
  узлов различается.
- Схема (4 колонки шагом 90 px, `colX = 45 + c × 90`, холст 360 px; ряды
  y = 44 / 144 / 244 / 344; корень в колонке 1.5):

  ```
                 корень (1.5)
     A (0.5)      AUTO (1.5)      B (2.5)
   A1 (0)  A2 (1)                B1 (2)  B2 (3)
   A1x (0)  A2x (1)              B1x (2)  B2x (3)
  ```

- Развилки (взаимоисключающие, `exclusive`): A ↔ B, A1 ↔ A2, B1 ↔ B2.
  Узел AUTO — без развилки, один на шарик, даёт эффект для авто-линии
  (раздел 17.9). Два уровня выбора на каждом пути: сторона и ветка.
- Открытый узел закрывает свою развилку: статус `blocked`, подпись «Путь
  закрыт выбором: сбросьте дерево». Выбор закрывается только сбросом.
- Идентификаторы: корень `тип:root`, узлы `тип:КЛЮЧ`, КЛЮЧ — auto, a, b,
  a1, a2, b1, b2, a1x, a2x, b1x, b2x. Например, `fire:a`, `mark:b2x`.
- Стоимость в ОП растёт: n-й открытый узел дерева стоит n ОП
  (`nextNodePoints`). Полное дерево — 66 ОП. Монеты по ряду: авто 60,
  ряд 1 — 40, ряд 2 — 80, ряд 3 — 150.
- Узел открывается, когда открыт родитель, шарик открыт, есть ОП именно
  этого шарика и монеты. Статусы (`nodeStatus`): `open`, `ready`, `locked`,
  `blocked`.
- Сброс (`resetTree`): все ОП шарика возвращаются (при n открытых узлах —
  n(n+1)/2), монеты — наполовину от суммы стоимости узлов.
- Эффекты узлов суммируются (`modsFor`), действуют на шарик, пока он стоит
  в колоде, и передаются движку через `startGame(cfg).mods`.
- Ключи эффектов (`ModKey`): `dmg`, `dmgPct`, `crit`, `shots`, `cd`,
  `combo`, `radius`, `chain`, `pierce`, `dur`, `slow`, `dps`, `stacks`,
  `needles`, `splash`, `ess`, `amp`, `drain`, `autoGap`, `autoPct`,
  `autoShots`, `autoCd`. Текст для игрока — `MOD_TEXT` / `describeMods`.
  Ключа `xp` больше нет.
- Окно шарика (`BallModal.tsx`): вкладка «Дерево» прокручивается вверх и
  вниз; карточка выбранного узла показывает эффект, цену в ОП и монетах.

### 17.9. Авто-линия

- Цепочка, сложенная в режиме совмещения (`firePair`, `fireChain`), из 2 и
  больше шариков по соседним клеткам запоминается как авто-линия (по id
  шариков) и остаётся активной: её шарики стреляют сами, когда готовы, без
  нового проведения (`engine.ts`: `autoLine`, `setAutoLine`, `runAutoLine`,
  `armAuto`). Сама сборка цепи по-прежнему только из одинаковых шариков
  (шипастый — с любым).
- Шипастый в линию не входит. Линия ломается, если пропало больше `autoGap`
  шариков (или осталось меньше двух). Новая линия заменяет старую.
- Залп авто-линии: `2 + autoShots` снарядов, урон × `1 + autoPct / 100`,
  перезарядка короче на `autoCd` с. Шарики линии, которые ещё перезаряжаются,
  пропускаются до готовности.
- Кнопка «Стоп линия» (`Hud.tsx`, `Controls`) видна, когда линия активна и
  включён режим совмещения.
- Моды (суммируются по колоде): `autoGap` — сколько шариков может пропасть
  без поломки; `autoPct` — урон авто-залпов, %; `autoShots` — снарядов в
  авто-залпе; `autoCd` — сокращение перезарядки авто-залпа, с.
- Узлы AUTO (раздел 17.8) дают по одному такому эффекту на шарик.

### 17.10. Вход и облачное сохранение (Firebase)

- Вход по логину и паролю, без почты. Логин: 3–20 символов, латинские
  буквы, цифры и «_», регистр не важен. Пароль: не меньше 6 символов.
  Логин превращается в служебный адрес `логин@orbital.app` для Firebase
  Email/Password. Адрес нигде не показывается и не проверяется.
- Конфиг в `src/firebase.ts` — публичные данные веб-приложения, не секрет.
  Защита данных — правила Firestore (`firestore.rules`).
- Облако: Firestore, документ `players/{uid}`. Игрок читает и пишет только
  свой документ. Новый аккаунт получает стартовую мету.
- Без входа игра не открывается. Выход очищает локальную копию меты.
- Что нужно сделать в консоли Firebase (проект `random-balls`):
  1. Authentication → Sign-in method → включить Email/Password;
  2. Firestore Database → создать базу (режим production);
  3. опубликовать правила: `firebase deploy --only firestore:rules`
     (файлы `firestore.rules` и `firebase.json` лежат в проекте) или
     вставить содержимое `firestore.rules` во вкладку «Rules».
- Не проверено: в песочнице `identitytoolkit.googleapis.com` недоступен
  (код 000). Поведение при открытии `index.html` по протоколу file:// тоже
  не проверено: сохранение сессии Firebase Auth и запросы могут вести себя
  иначе. Если вход не работает из file://, решение — публиковать игру на
  хостинге (например, Firebase Hosting).
